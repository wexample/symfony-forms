# Keep crawlers from indexing the form submit endpoints

Opened: 2026-10-27
Updated: 2026-10-27
Author: agent:main

Search Console of an application (`weeger.io`) lists `/_forms/submit/form-add_to_cart_form/entity/<id>`:
Google finds the address in a form's `action`, opens it in GET, gets `405` with an HTML error
page carrying `<meta name="robots" content="noindex">`. Not indexed, but only the HTML error
page says so; the JSON answers of a POST say nothing.

## Task

An `X-Robots-Tag: noindex` header on every response of the submit endpoints, the `405` of a GET
included — thrown before any route matches, so recognised by path as well as by route name.

Not robots.txt: a `Disallow` would hide the `405` and the `noindex` from the crawler, and an
address found through a link can then be listed "indexed, though blocked by robots.txt".

## Done

`src/EventSubscriber/FormRobotsResponseSubscriber.php` sets `X-Robots-Tag: noindex, nofollow`
on every response of the two submit routes, recognised by route name (any import prefix) and by
the `/_forms/` path (the `405` of a GET, which has no route). A header already set is left as it
is. `FormController` gains `ROUTE_NAME_PREFIX` and `PATH_PREFIX`.

`tests/Integration/FormRobotsResponseTest.php`: the `405` of a GET on both routes carries the
header, a POST too, any other address does not. Fails with the subscriber disabled. The fixture
now imports the forms routes and sets `disallow_search_engine_index: false` — a debug kernel
says `noindex` on everything, which hid the control case.

`composer.lock` refreshed: it no longer matched `composer.json` (`wexample/symfony-security`
missing), so `composer install` refused to run.
