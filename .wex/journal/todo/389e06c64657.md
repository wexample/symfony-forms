# A form that submits when a control changes

Opened: 2026-10-07
Author: agent:app:main

## Why

LDP's simulation bar (§11 of `MOJOE/local/poortere/ldp-production-planning/.wex/knowledge/specifications/platform-features.md.j2`):
the three controls exist here — `RadioInputType` `segmented`, `RangeInputType`, `SwitchInputType` — but
nothing submits the form when one of them moves. `auto_submit` exists on `OtpInputType` alone, for a code
that completes. weeger said go, 2026-10-07.

## Shape

The same split as `submit_when_valid` (`354095a`), which is the precedent to follow:

1. `AbstractForm::configureOptions()` — option `submit_on_change`, bool, false by default, pushed to
   `$view->vars` by `buildView()`.
2. `assets/form/form_theme.html.twig`, block `form_start` — `data-submit-on-change` on the `<form>`.
3. **`symfony-loader`, `assets/js/Class/Form.ts`** — the listener that reads the attribute and calls
   `requestSubmit()` on `change`. That half is outside this package: `submitsWhenValid` there is the
   model to mirror, ~15 lines. Not ours to write.

`change` and not `input`: a range fires `input` on every step and `change` on release, which is the
recompute wanted — one request per move, not one per pixel.
