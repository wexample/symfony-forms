# A form that submits when a control changes

Opened: 2026-10-07

## Why

LDP's simulation bar (§11 of `MOJOE/local/poortere/ldp-production-planning/.wex/knowledge/specifications/platform-features.md.j2`):
the three controls existed here — `RadioInputType` `segmented`, `RangeInputType`, `SwitchInputType` — but
nothing submitted the form when one of them moved. `auto_submit` was an `OtpInputType` option alone, for a
code that completes. weeger said go, 2026-10-07, the loader half included.

## Shape

The same split as `submit_when_valid` (`354095a`), which is the precedent followed:

1. `AbstractForm::configureOptions()` — option `submit_on_change`, bool, false by default, pushed to
   `$view->vars` by `buildView()`.
2. `assets/form/form_theme.html.twig`, block `form_start` — `data-submit-on-change` on the `<form>`.
3. `symfony-loader`, `assets/js/Class/Form.ts` — `submitsOnChange` reads the attribute, a `change`
   listener calls `requestSubmit()`, guarded by `isSubmitting`. `requestSubmit` and not `submit`, so the
   submit event is raised and the form goes its usual way: ajax for a form declaring `$ajax`, navigation
   otherwise.

`change` and not `input`: a range fires `input` on every step and `change` on release, which is the
recompute wanted — one request per move, not one per pixel.
